# homelab-agent-stack

一个人维护的**多机 AI Agent 运行环境**：一台低配云服务器当调度中枢，若干边缘机器跑实际负载，全部通过私有网络互联，用定时任务和故障自愈代替人工值守。

> 不是演示项目，是每天真在跑的系统。

## 这个项目解决什么问题

想长期跑 AI Agent，会撞上三个现实问题：

| 问题 | 常见做法 | 这个项目怎么做 |
|---|---|---|
| **常驻成本** | 买高性能云服务器 | 最便宜的共享型实例当大脑，重活外包 |
| **多机协同** | 每台机器各自为政 | 私有网络 + 统一调度 + 状态汇总 |
| **无人值守** | 挂了等人工发现 | 三层自愈 + 定时巡检 + 失败降级 |

核心原则：**中枢只做调度和通道，不做业务**。一台 2 核 2G 的机器能管住整个机群，是因为它从不亲自干活。

## 架构

```
                    ┌─────────────────────────┐
                    │   中枢（云服务器 2C2G）    │
                    │                         │
                    │  · 消息网关             │
                    │  · 定时任务调度          │
                    │  · 监控看板             │
                    │  · 知识库检索           │
                    └───────────┬─────────────┘
                                │  私有网络（Tailscale）
        ┌───────────────┬───────┴───────┬───────────────┐
        │               │               │               │
   ┌────▼────┐    ┌────▼────┐    ┌────▼────┐    ┌────▼────┐
   │ 边缘机 A │    │ 边缘机 B │    │ 边缘机 C │    │ 本地机   │
```

**每个节点只暴露内网地址，公网端口只留一个 SSH 入口。**

## 核心设计决策

### 1. 中枢轻量化

云端只跑三样东西：消息通道、调度器、监控。任何吃内存的负载一律外迁。

**代价**：中枢挂了全盘停摆。
**缓解**：三层自愈（见下）。

### 2. 私有网络做骨干

所有机器加入同一个 Tailscale 网络，服务只绑内网地址。

**收益**：不用开公网端口、不用配证书、不用买专线。
**代价**：Tailscale 挂了机器之间失联 —— 踩过的坑见 `docs/pitfalls.md`。

### 3. 三层故障自愈

```
第一层  systemd Restart=always        进程崩溃自动拉起
第二层  守护脚本（每 5 分钟）           进程在但无响应时强杀重启
第三层  巡检任务（每 15 分钟）          端到端验证业务可用
```

**为什么要三层**：单靠 systemd 救不了「进程活着但卡死」的情况；单靠巡检发现太慢。

### 4. 长任务用定时器，不用常驻进程

需要定期执行的事情全部交给 cron（系统 cron + 应用级调度器分工），不写常驻守护进程。

**收益**：内存占用接近零，可以跑几十个任务。
**代价**：只能按时间触发，做不到事件驱动。

### 5. 知识沉淀为纯文本

所有决策、踩坑、运维记录写成 markdown，用 git 管理，并建索引支持语义检索。

**收益**：人和模型都能读、能 diff、能回溯。
**代价**：需要定期整理，否则变成垃圾场。

## 技术栈

```
操作系统    Ubuntu LTS
网络        Tailscale（WireGuard）
调度        系统 cron + 应用级定时任务
监控        自建轻量看板 + CSV 时序记录
存储        markdown + git；向量索引用 embedding API
语言        Python（脚本）、Bash（运维）
```

**没有用**：Kubernetes、消息队列、分布式数据库。原因是单机编排的成本远超收益。

## 项目里值得说的几件事

- **2 核 2G 管住 5 台机器**：靠的是职责拆分，不是性能
- **从来不敢重启的那个服务**：进程不能自杀重启，只能外部触发（详见 pitfalls）
- **故障自愈的三层设计**：为什么 systemd 一层不够
- **成本意识**：每 GB 流量、每 MB 内存都有账，能查出异常是谁吃的
